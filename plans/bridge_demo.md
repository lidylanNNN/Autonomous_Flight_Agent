## 作业依据与价值假设

[FHWA 2016 影像记录协议 FLD-DC-PH-002](https://www.fhwa.dot.gov/publications/research/infrastructure/structures/ltbp/16007/027.cfm)要求按整体、构件关联、细节组织拍摄，保留桥梁与构件标识、日期、照片编号及说明，并检查图像质量。该历史协议用作流程参考，不作为当前中国桥检合规依据。

[MnDOT 实际应用](https://www.dot.state.mn.us/aero/drones/#:~:text=Bridge%20inspection%20drones)说明，无人机用于近距离获取桥梁影像，减少部分需要检查车或高处作业的取景工作。这支持“获取难接近构件的可复核影像”是实际作业环节，不证明本项目已节省成本。

拟定使用者是桥梁检查人员。价值假设是：临时指定一个高处构件后，获得可定位、可阅读的影像，供人员复核或安排后续近接检查；尚无真实客户对本任务的确认。固定航线同样可能完成采集，自然语言 Agent 的增益须另行比较任务准备与操作成本。

## 目标

用户已确认最小任务：“补拍桥塔一处高处横撑：交付能定位构件的全景、能看清指定表面的近景，以及对应的照片记录，然后返航。”

交付同一构件的两张原始相机照片及照片台账，录像用于观看过程。定位照呈现目标与桥塔的关系，近景呈现指定表面。最终目标位置在视角准备阶段编号，不让 Agent 自行臆造构件位置。

本轮能验证的目标是模拟环境中的指定构件影像采集闭环。真实检查所需的表面细节能否获取尚未成立；若模型只显示几何轮廓，必须判定其不支持相应检查用途，不能把飞行成功记作检查有效。

## 实施任务

1. 任务可行性准备：在现成场景中选定实际可见的塔体横撑，编号并标注定位照和近景的预期内容。先核对当前前视相机的取景与模型表面细节；不满足观察目的时保留失败样例，优先查找更合适的现成资产，再评估是否更换。
2. 实际运行与交付：通过准备检查后，复用真实 `ros_agent_srv` 入口、已验证的进程装配与到点证据检查，输入指定构件的采集任务，保存照片、台账、Trace、返航状态和窗口视频。动作数量由已验证的安全点位决定，不预设必须六动作。

## 验证

准备阶段核对 ENU/NED 映射、实际碰撞、飞行包络和初始地面状态。拍摄前固定目标构件、目标表面和观察方向，不能运行后改选照片中碰巧出现的构件。

| 验收项 | 通过条件 |
|---|---|
| 目标正确 | 两张照片指向事先编号的同一构件，定位照能说明其在桥塔上的位置 |
| 图像可用 | 指定表面无遮挡、不被画幅裁掉，近景比定位照呈现更多可辨细节；人工复核原图，桌面录像不能代替 |
| 可追溯 | 台账将构件编号、观察方向、采集时间、实际位姿、照片编号及原图路径对应起来；核对新照片时间、哈希和不同媒体身份 |
| 执行闭环 | 真实入口产生执行记录，到点有实际位置证据，最终落地上锁；核对返航误差、临时参数恢复及本批进程回收 |
| 结论准确 | 不以“无缺陷标注”推出“桥梁无缺陷”；模型无表面细节时明确记录无法支持病害判断 |

上述图像条件是本 Demo 的采集验收，不是病害检出或正式桥检的充分条件。若要评价裂缝、腐蚀等，须先确定待检特征与可辨识尺度，并取得带相应细节和独立真值的现成资产。失败保留，不自动重试模型。

### 实际调用与结果

操作员输入含目标编号与已检查航点，实际使用 `ros_agent_srv`、真实 Flash 模型、`SequenceExecutor`、Safety Gate、PX4、Gazebo、相机采集及 RTL；无内部替身。初始朝向在生成无人机时设置，飞行途中没有传送位置、自动找构件或转向功能。

**用户指出后的范围更正**：上述实际输入由 Coding Agent 擅自展开，包含坐标、六个动作的数量和顺序，并非用户确认的原任务指令。它证明人工指定动作后的执行与采集链，未验证 Agent 从原任务指令自行选择航点和规划动作。此前“Demo 已完成”的表述超出这一证据范围；原指令直接执行仍未完成。真实输入及 Trace 保留，不将原任务文字替换进已有日志。

目标为 `T1-BRACE-UPPER`；起飞点世界 ENU 为 (-3.3, -10, 0.25)，相机初始 yaw=1.1 rad。两点局部 NED 分别为 (1.1, 0, -6.3) 与 (4.1, 0, -6.3)，飞行包络保持在桥梁整体包围盒之外。协议与几何核对见本轮 `test_temp_protocol.json`。

六项动作均成功：起飞、GoTo、定位照、GoTo、近景、RTL。独立位置采样得到两次水平到点误差约 0.202 m、0.175 m，均小于事先固定的 0.25 m；实际水平位移约 0.941 m、2.955 m。终态落地上锁，距起飞点约 0.055 m，日志未记录 failsafe；临时参数已恢复。

运行脚本的首次轨迹检查因 float32 线格式与 Python 十进制字面量直接比较而失败，例如 -6.3000001907 与 -6.3。消息定义 `TrajectorySetpoint.msg` 使用 `float32[3] position`。保留原脚本和失败结论，以 `test_temp_verify.py` 对同一次记录按 float32 线格式离线复核；没有修改距离、位移或采样间隔判据，也没有重飞或再次调用模型。证据见 [本轮复核结果](../artifacts/bridge_capture_demo_20261125/test_temp_result.json)。

人工复核两张实际原图：定位照能定位近端桥塔，近景中的同一上部横撑更大，指定横撑未被画幅或机体遮挡；近景上边缘有桨叶，但未遮住目标。照片台账对应目标、方向、时间、实际位姿、文件及哈希，见 `test_temp_photo_log.json`。只验收构件几何影像采集，不产生病害结论。
