状态：实施中，1a/1b 已完成替身验证，2a-1 已完成核对，2a-2 连接设计已确认待实施；2026-11-09 基于 `3f317a7` 开始。各批完成范围以实施记录为准，M5 整体验收尚未完成。

- `RosEnv.step()` 日志已报告执行结果，但返回 `info={}`；下一轮 prompt 只有人工文本、观察和动作库，没有上一轮执行诊断。
- 既有主链证据来自真实入口加外部替身，范围见 [MX-5 审计](MX-5-audit.md)。该记录中的旧 Authority 和旧审批状态已由 M4 更新，不作为当前事实。

## 目标

从现有生产入口完成一轮：操作员输入自然语言，真实模型根据实际状态摘要和动作说明输出有限序列，经现有 Gate 执行，向操作员返回执行事实和新观察，然后等待人工输入。

首轮通过 DeepSeek 官方云端 API 调用 `deepseek-flash`，使用非思考模式作为本项目 M5 基线。当前官方映射为 DeepSeek-V4.1-Flash-1017，接口与价格依据见[官方文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。ROS-LLM 论文使用 Deepseek 7B Coder，本项目保留其调用拓扑，不宣称复现论文模型；Coder 6.7B 不再作为首轮接入要求。

M5 交付包括可追踪的真实模型调用、完整多动作提取、明确的无效输出处理，以及独立进程运行的受控 SITL 主链证据。任务完成判定仍由 M6 补齐。

## 约束

- 首轮使用 `https://api.deepseek.com`，不新建专用付费端点。记录服务模型名、官方版本映射、调用日期及返回的模型标识；云端别名可能更新，不宣称固定权重 revision。
- M5 首轮模型调用消费上限为人民币 1 元，不等于账户充值金额。按实际 usage 与当时费率核算，继续调用可能超出剩余额度时停止并报告；尚未实现自动预算拦截，不把请求数或 512 token 输出上限当作费用保证。
- 连接使用 `FLIGHT_LLM_API_KEY`、`FLIGHT_LLM_BASE_URL`、`FLIGHT_LLM_MODEL` 环境变量。采用 Python 标准库 HTTP，不新增模型 SDK；单次模型请求超时 30 秒，最大输出 512 token。Agent 等待预算须覆盖请求时限并留通信余量。
- 模型整个回复须恰为一个 JSON 代码块，内部为 JSON Lines；保持现有严格提取规则，不增加说明文字或裸 JSON Lines 兼容。
- 首轮 SITL 起飞高度 3 米、系统高度上限 5 米；围栏、限速等沿用核对后的 M4 配置。
- 密钥仅由运行进程从环境变量读取，不经源码、ROS 参数或命令行参数传值；本地密钥存于 Git 忽略的 `.env`，权限 `600`，启动时加载；真实值不得进入受版本管理的文件、日志、Trace、异常回显或对话输出。测试只使用虚构值验证读取与脱敏。
- 拓扑与安全边界以 [SPEC 第 4、5 节](../SPEC_DEV.md)为准；服务字段以 [服务契约](../contracts/rosllm_services.md)为准。
- 保留 JSON Lines 序列、五动作白名单和当前 16 项上限；不因兼容模型输出扩大动作权限。
- 不新增任务 ID、MissionPlan、通用 Hooks、第二套 Safety 或自动重试飞行动作。
- M5 只证明下一轮仍由人工触发；失败后依据反馈生成修正行为的专项验收归 M7，无人续跑不进入本计划。
- `INCONCLUSIVE` 不解释为任务成功；模型回复、执行成功与任务成功分别报告。
- 明确执行失败后停止原序列并自动尝试一次 5 秒 Hold，不调用模型决定处置。Hold 仍经过现有 Gate，不绕过状态、权限或 Trace 检查；Hold 失败不得递归重试，也不自动升级 RTL。失败动作与 Hold 结果分别保留。Gate 拒绝与不确定超时仅单独报告，不触发该自动处置；Hold 到期后的飞行行为须核对现有 Backend。
- 每批遵循 [AGENT.md](../AGENT.md)的规模和审核规则。下面是拆分顺序，不是对未确定接口、外部依赖或安全行为变更的提前批准。

## 实施任务

下表每行是一个评审批次；一级步骤只保留阶段职责。实现批次同时包含该目标必需的测试和文档，验收条件集中列在“验证”节。

默认每批限一个模块边界、300 行以内语义改动。表中的文件是允许触及的边界，不要求全部修改。开始实施前核对实际差异；必须联动的接口和调用方保持同批，预计超出阈值则重新拆分。结构变更按 AGENT.md 先记录影响和回滚并确认，不以拆小行数免除审核。

## 生产调用流

现有拓扑见 [SPEC 第 4 节](../SPEC_DEV.md#4-ros-llm-对齐的目标调用链)，实际替身证据见 [MX-5](MX-5-audit.md#实际调用流)。M5 计划替换以下边的数据内容，不改变主循环：

```text
Px4WorldStateAdapter --WorldState--> ObservationManagerNode
ObservationManagerNode --Observation.Response(实际状态摘要)--> RosEnv
RosEnv --观察--> ros_agent_srv.main
操作员 --人工任务--> ros_agent_srv.main
ros_agent_srv.main --人工任务与观察--> RosAgent
RosAgent --LLM.Request(prompt 含动作描述)--> LLMNode
LLMNode --有界生成请求--> 模型供应商
```

### 目标

由启动 LLMNode 的 Shell 显式 `source .env`，进程只读取环境；节点不自行搜索或读取密钥文件，密钥不作为 ROS 参数或命令行值。固定开发模式不要求凭据、不访问网络，继续保留原来源标记；真实调用失败时不得自动退回固定行为。

### 对象职责与文件边界

LLMNode 继续由 `llm_node.main()` 创建和持有，独占 `call_llm` 服务；默认串行回调避免同一节点并行消费。HTTP 请求构造、发送和响应检查作为 llm_node.py 内部函数，只有服务回调调用，不单独建立 Provider 类或任务调度器。RosAgent 仅调整模型调用的等待预算，不承担网络认证或执行重试。

预计修改 `agent_comm/agent_comm/llm_node.py`、`ros_agent_srv.py` 的模型等待参数及对应测试；请求与响应处理尽量不超过一个可评审实现批次。两个服务边界必须同改才能形成可用链路，实施前按实际规模汇报，不提前批量创建组件。

### 请求与返回

使用 `urllib.request`，POST 到配置来源下的 `/chat/completions`。请求为 UTF-8 JSON，认证仅置于 Authorization 请求头；拒绝 HTTP 重定向，避免凭据随跳转传播。

```json
{
  "model": "deepseek-flash",
  "messages": [{"role": "user", "content": "<LLM.Request.prompt 原文>"}],
  "thinking": {"type": "disabled"},
  "max_tokens": 512,
  "stream": false,
  "temperature": 0
}
```

首轮沿用上游的单条 user message，2b-1 在实际 prompt 中明确动作输出格式。JSON object 响应模式与当前 fenced JSON Lines 契约不一致，因此不启用。温度为本项目的低随机性设置，不承诺结果完全可复现。

HTTP 200 后要求 choices 恰有一个候选，候选为 assistant 消息，content 为非空字符串，finish_reason 为 stop，且无 tool_calls。保留原始 content，不 strip 后覆盖、不补全、不在节点中提取动作；原文交给 RosAgent 记录，再由现有提取与执行器校验。模型接口成功仅表示拿到完整文本，不代表序列合法或任务成功。

正常响应的 info 使用 JSON 字符串，包含 source=deepseek_api、实际返回 model、response_id、finish_reason、原始 usage 和 error_code=null。失败同样提供来源与稳定错误码；response 必须为空。固定模式 info 保持既有字符串，不强制迁移旧记录。现有 TraceRecorder 原样保存 info，无需改 Trace 或 ROS Contract。

### 超时与故障

HTTP I/O timeout 设为 30 秒；Agent 发现模型服务保留 5 秒预算，等待模型响应使用独立 35 秒预算，不放大观察服务的 5 秒等待。必须区分服务发现与响应等待，不能把 35 秒同时套给两者后声称总计只有 35 秒。

标准库 timeout 不是远端取消，也不保证整个传输的绝对墙钟上限；客户端超时后停止本轮，不派发迟到回复、不自动重发。后续若要求严格的进程级截止时间，另立实现批次，不在本轮暗加取消协议。HTTP 响应读取限制为 256 KiB，避免无界响应；超限直接失败。

| 条件 | 返回错误码 | 后续行为 |
|---|---|---|
| 缺少凭据、无效地址或非基线模型 | LLM_CONFIG_ERROR | 不发 HTTP 请求 |
| HTTP 401/402/429/其他非 200 | LLM_HTTP_ERROR，另记状态数字 | 不回显供应商响应体，不自动重试 |
| 网络、TLS 或 I/O 超时 | LLM_NETWORK_ERROR / LLM_TIMEOUT | 费用可能未知，停止后续真实调用直至核对 |
| 非 JSON、错误结构、空内容、工具调用 | LLM_INVALID_RESPONSE | 失败，不生成行为；已有 usage 仍保留 |
| finish_reason=length | LLM_TRUNCATED | 不执行截断行为，不自动追加 token 重发 |
| 其余非 stop 结束原因 | LLM_INCOMPLETE | 失败并保留结束标记 |
| 缺失或不一致的 usage | LLM_USAGE_UNAVAILABLE | 不放行为，停止后续真实调用并核对账单 |

错误信息只含稳定码和必要状态数字，不拼接原异常全文、请求头或 HTTP 错误体。即使正文被拒绝，其已发生的用量仍需核算。客户端服务调用异常仍由主入口捕获、再观察并等待人工输入，不新增飞行动作。

### 用量与首轮预算

首轮由受控测试操作者串行运行并维护同一份消费记录；不让通用 LLM 服务承担账户余额管理，不新增持久化预算框架。每次请求返回后先记录 usage 和计费时间，再决定能否执行下一次付费测试；进程重启不代表预算重置。现有 Agent Trace 中的 info 保存模型与 usage；测试直接调用节点时须自行保存返回值作为证据，不能假定其经过 Agent Trace。

按官方 usage 中的输入缓存命中、未命中及输出 token 分别核算，使用 Decimal，费率绑定本轮价格页核对日期。为避免跨计费时段误差，预算判断可统一采用已核对的高峰费率作保守累计；报告中区分本地估算与平台最终账单，不把赠送余额抵扣当作没有消费。

开始真实生成前先执行一个短请求，检查 usage 与预计费用；后续仅在剩余预算足以覆盖计划请求时继续。首轮 prompt 限定为现有五动作说明、当前观察和短人工任务，不发送任意长历史。不能用字符数、调用次数或仅输出上限声称严格计费上界；无法确认某次请求费用或下一次预算时停止，不擅自提高 1 元额度。当前尚无自动预算拦截，本设计明确采用人工逐次核算，不宣称供应商账户具备本项目专属硬限额。

### 计划调用流

```text
启动 Shell --已导出环境配置--> LLMNode
RosAgent --LLM.Request(prompt)--> LLMNode.get_response
LLMNode.get_response --单次 HTTP 请求--> DeepSeek Chat Completions
DeepSeek Chat Completions --HTTP 状态、content 与 usage--> LLMNode.get_response
LLMNode --LLM.Response(success, response, info)--> RosAgent
RosAgent --实际 prompt 与完整响应--> TraceRecorder
RosAgent --LLM.Response--> ros_agent_srv.main
操作者 --本轮 usage 与费率核算结果--> 本轮消费记录
```
