# M6 — 视觉场景功能 Test（一周）

状态：2026-11-17 按用户决定，M6 只负责视觉接入和有用场景功能 test，时间盒一周；系统性能 eval 独立到 M7。尚未实施，不将计划或固定用例通过宣称为系统性能。

## 1. 现状

当前生产主链与阶段证据见 [SPEC_DEV 第 2、4 节](../SPEC_DEV.md)及 [M5 收口审查](M5.md#4c-收口审查)。有人入口调用模型生成有限动作序列，逐项执行，经 Gate 调用 PX4 Backend，结束后再观察并等待人输入。当前开放五动作，尚未接入相机采集、目标检测及本表其他扩展服务。

环境冻结为 PX4 v1.16.2、Gazebo Harmonic、ROS 2 Jazzy，准确提交见[环境清单](../manifests/environment.yaml)。下表评估 PX4 版本具备的能力，不以本项目当前五动作接口为上限。

本机 PX4 checkout 的 `Tools/simulation/gz` 子模块提交为 `e05f4312d3f28aa621157610584a4870406cb6d3`。只读清单已确认含 `default.sdf`、`aruco.sdf`、`baylands.sdf`、`walls.sdf` 等世界，以及 `x500_mono_cam`、`x500_mono_cam_down`、`x500_depth`、`x500_gimbal` 机型；文件存在不等于相机或视觉场景已运行通过。当前 [start_simulation.sh](../scripts/ros2_px4/start_simulation.sh)仍固定启动 `HEADLESS=1 make px4_sitl gz_x500`，未提供世界/机型选择入口，也未证明无窗口相机渲染和图像桥接已接入。

本机只读检查结果：i9-13900HX（24 核、32 线程）、RTX 4060 Laptop（宿主机查询显存 8188 MiB，驱动 595.99.02）、16GB 系统内存、NVMe 文件系统剩余约 367GB。查询时可用内存约 5.6GiB、交换空间占用约 3.4GiB；这些是瞬时占用，不是场景峰值。沙箱未暴露 GPU 设备节点，不能将沙箱内 `nvidia-smi` 失败判为宿主机驱动故障。

现行[测评设计](../docs/eval_doc/v1_evaluation.md)定义系统评分及证据口径；现无完整系统基线评分。本阶段只产出功能证据；后续量化运行、判分和比较见 [M7](M7.md)，不在 M6 实施。

## 2. 目标

一周内先证明一个有用视觉任务能工作：“飞到指定点，检查指定类别目标，返回检测结果和对应图片，然后返航/着陆”。选择现成工具已支持的一类目标（人或车），不要求同时支持所有业务目标。

M6 的“有用指标”是可核对的功能验收项：是否到点、实际图片是否保存、检测器是否消费本次图片、结论是否符合预定场景、返回结果是否与图片对应、是否返航/着陆，以及失败是否被如实报告。固定用例通过不推导总体成功率。

完整系统成功率、未见/扰动成绩、耗时/成本、安全及基线差值由下一周的 [M7](M7.md)负责；M6 不同时建设 eval。

## 3. 范围与约束

- 顺序固定为 M6 功能 test 通过后进入 M7。M6 交付真实模型、ROS 2、Gate、PX4/Gazebo 相机和现成检测工具的实际调用，不以 Mock 或纯起降替代。
- 复用冻结相机机型、一个简单世界和少量许可明确的静态模型；单路 RGB、一种目标类别、已知坐标、一条主要任务序列。多点只用两个预定点复用同一工具链，不建自主搜索。
- 只验证一种实际可运行的图像/渲染模式；不同时完善 GUI、云端 EGL、通用资源下载器或多相机兼容。这是相对之前宽估范围的实际删减，不能把同样工作量直接改写成一周。
- 不训练/微调视觉模型，不优化业务工具效果。工具必须在所选功能场景满足要求；否则记依赖缺口，不能以“调用正确”宣布有用。
- 五动作、主入口和 Safety 保持既有边界；不增加条件分支平台、自动恢复、Orbit/Mission、录像、三维定位或载荷。
- 真值只用于 test，不能输入 Agent 或检测器；旧图、固定检测成功、仅传媒体引用而不消费都不算通过。
- 更复杂场景留 [V2-4](V2-optimizations.md#v2-4从-m6-迁出的场景扩展)。本次只拆分计划，不实施或新增付费运行。

## 6. 生产接入位置

只修改必要的启动配置、动作库、采集/检测适配服务、契约、功能测试和手册，不预建 `eval_harness` 平台。新增对象在对应批次明确创建者、持有者和调用条件。

拟议链路（尚未接入）：

```text
[SequenceExecutor] --AtomicActionRequest--> [采集服务；待接入]
[Gazebo 相机] --实际图像、参数及时间--> [采集服务的图像接入对象；待接入]
[采集服务；待接入] --图片及元数据--> [媒体存储；待接入]
[媒体存储；待接入] --媒体引用--> [采集服务；待接入]
[采集服务；待接入] --AtomicActionResponse--> [SequenceExecutor]
[SequenceExecutor] --AtomicActionRequest（媒体引用、类别）--> [检测服务；待接入]
[检测服务；待接入] --图片读取请求--> [媒体存储；待接入]
[媒体存储；待接入] --实际图片--> [检测服务；待接入]
[检测服务；待接入] --图片及类别--> [现成检测工具]
[现成检测工具] --检测结果或错误--> [检测服务；待接入]
[检测服务；待接入] --AtomicActionResponse--> [SequenceExecutor]
```

物理动作继续通过既有 Gate/Backend；检测输出及对应图片需通过实际终端结果或可访问产物交付，不能只存在测试内存中。

## 7. 功能 Test 验收

### T1：先证明场景有用

固定功能集合在执行前确定，不根据检测结果临时挑一张成功图片：

- 有目标：实际输入驱动到点、取得新图片、现成工具检测出预期类别、返回结论及对应图片，实际返航/着陆。
- 无目标：返回该画面的未检出结果与图片，不捏造目标，不夸大为整个区域无目标。
- 两点：图片/结果逐点对应，时间和位置引用可追溯，不复用前一点旧图。
- 失败：相机无图、工具不可用或超时明确失败，停止后续派发，不假成功。错误替身只补故障覆盖，不能证明正向业务可用。

T1 只判这些场景是否工作，不规定总体准确率或泛化指标；业务工具在固定场景效果不足时反馈依赖缺口，不转成我们训练模型。

| 批次 | 最小评审证据 |
|---|---|
| T01 | 资源来源、许可、版本与配置清单，固定配置可启动/重置，默认入口回归。 |
| T02 | 真实图像/相机参数/仿真时间对应，过期或无图不报有效。 |
| T03 | 实际主入口调用采集，图片可读取，写入失败不报成功。 |
| T04 | 图片被真实工具实际消费，结果、版本及错误可关联。 |
| T05 | 单点/两点任务的实际命令、状态、图片与结果齐全；目标/返航由真实证据核对。 |
| T06 | 无目标与失败行为符合契约，明确真实调用与替身边界。 |
| T07 | 固定集合复跑结果、未完成项及可复现交接包齐全，不声称已测系统成功率。 |

## 8. 交接与止损

M6 通过标准是 T1 真实场景 test 和 T07 交接，不含系统 eval。交给 M7 的是可用工具链、固定运行入口、功能样本、原始证据及当前版本；统计矩阵、批量 Runner、Grader 和比较报告均在 M7 实施。

到一周末未通过就列明阻断及尚未满足的功能项，M7 不得跳过可用性前提；不伪造通过、不删视觉、不默认侵占 RSI/面试时间。新增配置/接口可按批回滚，原五动作回归与安全边界保持，历史 artifacts 保留。
