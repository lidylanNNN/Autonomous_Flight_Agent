# M6 — 视觉场景功能 Test（一周）

状态：2026-11-18 更新；按用户决定，M6 只负责视觉接入和有用场景功能 test，时间盒一周；系统性能 eval 独立到 M7。T01a–T04d 已完成环境、采集、检测及地面交付验证；T05a 已通过单点飞行视觉闭环，证据见下方实施记录。T05b、T06、T07 尚未收口；不将固定用例通过宣称为系统性能。

## 1. 现状

当前生产主链与阶段证据见 [SPEC_DEV 第 2、4 节](../SPEC_DEV.md)及 [M5 收口审查](M5.md#4c-收口审查)。有人入口调用模型生成有限动作序列，飞行动作经 Gate 调用 PX4 Backend，结束后再观察并等待人输入。当前开放五飞行动作、拍照及人物检测；拍照证据见 T03b/T03c，检测服务与 Agent 串联证据见 T04b/T04c。

`RosEnv` 已能按共享白名单区分飞行与拍照说明。执行器逐项传递 `prev_output` 并返回原始步骤结果；有人入口已保存独立 JSON 并在终端显示图片引用、检测输出及文件路径。真实单点飞行返航后交付已按 T05a 验证，接口见 [T04d 契约](../contracts/rosllm_services.md#m6-t04d-逐项结果交付)。

环境冻结为 PX4 v1.16.2、Gazebo Harmonic、ROS 2 Jazzy，准确提交见[环境清单](../manifests/environment.yaml)。下表评估 PX4 版本具备的能力，不以本项目当前五动作接口为上限。

本机 PX4 checkout 的 `Tools/simulation/gz` 子模块提交为 `e05f4312d3f28aa621157610584a4870406cb6d3`。只读清单已确认含 `default.sdf`、`aruco.sdf`、`baylands.sdf`、`walls.sdf` 等世界，以及 `x500_mono_cam`、`x500_mono_cam_down`、`x500_depth`、`x500_gimbal` 机型；文件存在不等于相机或视觉场景已运行通过。[start_simulation.sh](../scripts/ros2_px4/start_simulation.sh)已增加默认/前视单目机型选择，实际启动证据见下文 T01a 记录；T01b 已接入单人物场景配置，T01c 已取得无窗口原生相机有效图片及检测结果，T02a 已验证所选组合的 ROS 图像桥接，见对应记录；通用世界选择仍未验证。

本机只读检查结果：i9-13900HX（24 核、32 线程）、RTX 4060 Laptop（宿主机查询显存 8188 MiB，驱动 595.99.02）、16GB 系统内存、NVMe 文件系统剩余约 367GB。查询时可用内存约 5.6GiB、交换空间占用约 3.4GiB；这些是瞬时占用，不是场景峰值。沙箱未暴露 GPU 设备节点，不能将沙箱内 `nvidia-smi` 失败判为宿主机驱动故障。

现行[测评设计](../docs/eval_doc/v1_evaluation.md)定义系统评分及证据口径；现无完整系统基线评分。本阶段只产出功能证据；后续量化运行、判分和比较见 [M7](M7.md)，不在 M6 实施。

## 2. 目标

一周内先证明一个有用视觉任务能工作：“飞到指定点，检查指定类别目标，返回检测结果和对应图片，然后返航/着陆”。选择现成工具已支持的一类目标（人或车），不要求同时支持所有业务目标。

M6 的“有用指标”是可核对的功能验收项：是否到点、实际图片是否保存、检测器是否消费本次图片、结论是否符合预定场景、返回结果是否与图片对应、是否返航/着陆，以及失败是否被如实报告。固定用例通过不推导总体成功率。

完整系统成功率、未见/扰动成绩、耗时/成本、安全及基线差值由下一周的 [M7](M7.md)负责；M6 不同时建设 eval。

## 3. 范围与约束

- 顺序固定为 M6 功能 test 通过后进入 M7。M6 交付真实模型、ROS 2、Gate、PX4/Gazebo 相机和现成检测工具的实际调用，不以 Mock 或纯起降替代。
- 复用冻结相机机型、一个简单世界和少量许可明确的静态模型；单路 RGB、一种目标类别、已知坐标、一条主要任务序列。多点只用两个预定点复用同一工具链，不建自主搜索。
- 只验证一种实际可运行的图像/渲染模式；不同时完善 GUI、云端 EGL、通用资源下载器或多相机兼容。这是相对之前宽估范围的实际删减，不能把同样工作量直接改写成一周。
- 不训练/微调视觉模型，不优化业务工具效果。工具必须在所选功能场景满足要求；否则记依赖缺口，不能以“调用正确”宣布有用。
- 五动作、主入口和 Safety 保持既有边界；不增加条件分支平台、自动恢复、Orbit/Mission、录像、三维定位或载荷。
- 真值只用于 test，不能输入 Agent 或检测器；旧图、固定检测成功、仅传媒体引用而不消费都不算通过。
- 更复杂场景留 [V2-4](V2-optimizations.md#v2-4从-m6-迁出的场景扩展)。本次只拆分计划，不实施或新增付费运行。

## 5. 最小可评审批次与一周时间盒

一周按 5 个有效开发日、每日约 6 小时安排。保留四个大步骤和 T01–T07 工作包，细分为 **19 个可独立评审子批次**；实施、验证及文档合计 27 小时，阻断修复预留 3 小时。拆分不增加功能范围，也不保证实际工期；评审等待、依赖交付与环境排障单列阻断。

每次只执行一个子批次，提交对应差异与第 7 节证据供评审；默认不超过 300 行语义改动。必须同改才能运行的接口和调用方同批；若实际超过阈值，按 [AGENT.md](../AGENT.md#小步变更与审核)重新拆分或确认，不交付失配的接口。小时数包含对应验证和文档，不是纯编码时间。

新文件名均为拟议落点，尚不存在；以对应设计批次确认后的路径为准。每个实现批次只同步自身使用说明及阶段记录，不另建平行权威定义。
