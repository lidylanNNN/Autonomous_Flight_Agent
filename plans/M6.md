环境冻结为 PX4 v1.16.2、Gazebo Harmonic、ROS 2 Jazzy，准确提交见[环境清单](../manifests/environment.yaml)。下表评估 PX4 版本具备的能力，不以本项目当前五动作接口为上限。

## 2. 目标

一周内先证明一个有用视觉任务能工作：“飞到指定点，检查指定类别目标，返回检测结果和对应图片，然后返航/着陆”。选择现成工具已支持的一类目标（人或车），不要求同时支持所有业务目标。

M6 的“有用指标”是可核对的功能验收项：是否到点、实际图片是否保存、检测器是否消费本次图片、结论是否符合预定场景、返回结果是否与图片对应、是否返航/着陆，以及失败是否被如实报告。固定用例通过不推导总体成功率。

完整系统成功率、未见/扰动成绩、耗时/成本、安全及基线差值由下一周的 [M7](M7.md)负责；M6 不同时建设 eval。

## 3. 范围与约束

- 顺序固定为 M6 功能 test 通过后进入 M7。M6 交付真实模型、ROS 2、Gate、PX4/Gazebo 相机和现成检测工具的实际调用，不以 Mock 或纯起降替代。
- 复用冻结相机机型、一个简单世界和少量许可明确的静态模型；单路 RGB、一种目标类别、已知坐标、一条主要任务序列。多点只用两个预定点复用同一工具链，不建自主搜索。
- 只验证一种实际可运行的图像/渲染模式；不同时完善 GUI、云端 EGL、通用资源下载器或多相机兼容。这是相对之前宽估范围的实际删减，不能把同样工作量直接改写成一周。
- 不训练/微调视觉模型，不优化业务工具效果。工具必须在所选功能场景满足要求；否则记依赖缺口，不能以“调用正确”宣布有用。
- 五动作、主入口和 Safety 保持既有边界；不增加条件分支平台、自动恢复、Orbit/Mission、录像、三维定位或载荷。
- 真值只用于 test，不能输入 Agent 或检测器；旧图、固定检测成功、仅传媒体引用而不消费都不算通过。
- 更复杂场景留 [V2-4](V2-optimizations.md#v2-4从-m6-迁出的场景扩展)。本次只拆分计划，不实施或新增付费运行。

## 5. 最小可评审批次与一周时间盒

一周按 5 个有效开发日、每日约 6 小时安排。保留四个大步骤和 T01–T07 工作包，细分为 **19 个可独立评审子批次**；实施、验证及文档合计 27 小时，阻断修复预留 3 小时。拆分不增加功能范围，也不保证实际工期；评审等待、依赖交付与环境排障单列阻断。

每次只执行一个子批次，提交对应差异与第 7 节证据供评审；默认不超过 300 行语义改动。必须同改才能运行的接口和调用方同批；若实际超过阈值，按 [AGENT.md](../AGENT.md#小步变更与审核)重新拆分或确认，不交付失配的接口。小时数包含对应验证和文档，不是纯编码时间。

新文件名均为拟议落点，尚不存在；以对应设计批次确认后的路径为准。每个实现批次只同步自身使用说明及阶段记录，不另建平行权威定义。

### T07a RTL 状态时序排查（2026-11-19）

#### 已确认机制

用户要求先将问题补入面试案例 Q02，再排查原因。本批只更新记录和诊断产物，未修改业务代码、安全阈值或验收判据，未再次调用模型或执行飞行动作。

生产 `SafetyExecutionGate.submit()` 读取并深复制状态后交给 `SafetySupervisor.evaluate()`；Supervisor 完成初检后等待 `read_validated_speed_limit()`，再对同一状态执行末次时效复核。`Px4WorldStateAdapter.read_world_state()` 返回最新缓存，不在读取时重新聚合；后续定时器生成的新快照不会替换正在审查的副本。因此，“参数读取期间有更新”不等于“当前提案使用的状态仍有效”。

参数适配器每次新建 MAVLink 连接，先等待目标心跳，再请求限速参数；它用 `asyncio.to_thread()` 执行阻塞读取，单次期限三秒。该期限可能长于位置剩余有效期；但 `to_thread` 不能据名称或用法推导为“所有 ROS 回调都被阻塞”。原飞行服务使用四线程 Executor，状态节点与动作节点分别持有回调组。

### T07a 分派循环与观测开销定位（2026-11-19）

#### 目的与观测方式

用户要求继续定位分派线程为何长时间计算。本批只扩展既有验证观察脚本，保持四线程、原输入及 Safety 行为。先用原生 cProfile 查看回调选择内部，再增加直接计数，最终用 `FLIGHT_TEST_DISPATCH_PROFILE=counters` 关闭飞行动作进程的 Python profile 和 cProfile，只保留入口响应记录、线程独立时钟与可执行性计数，控制此前观测开销。

诊断在进程内包装 `Executor.wait_for_ready_callbacks/can_execute/get_nodes`，保留原参数、返回和异常；没有修改安装的 rclpy 或业务文件。计数器统计实际扫描轮数、实体已经被调度与回调组不允许等原因，不用 profiler 的函数计数代替直接计数。内存保留首 100 次不少于 20 ms 的调用，并另外记录全部调用的最大墙钟及线程 CPU 时间；短调用未逐项保留。

#### 观测工具一致性问题

原生 cProfile 数据出现函数 self time 大于 inclusive time 的不一致，函数级耗时不能用于精确归因。已保存纯 CPU、无 ROS 的最小复现：三次单线程试验无不一致，三次其他线程同时启用 Python profile 的试验均出现不一致。另一次原生多线程试验也出现过不一致，故不把问题限定为仅由混用导致，更不认定为 ROS 业务故障。

此前原生 profiler 显示的具体函数耗时及扫描次数均降为线索；本节关于循环次数的结论只采用最终无 profiler 的直接计数。独立的外层单调/线程 CPU 时钟与实际状态 Trace 仍分别保留，不能把整份诊断数据一并当作有效或无效。

#### 三轮运行与最终计数

三轮均为原空场景任务的诊断运行，不是固定集合验收重试。原生剖析轮 `artifacts/m6_t06a/20261119T020046432399Z/` 为 `1 passed, 2 deselected in 49.60s`；原生剖析加原因计数轮 `20261119T020334016039Z/` 为 `1 passed, 2 deselected in 46.94s`；关闭 profiler 的直接计数轮 `20261119T020811667311Z/` 为 `1 passed, 2 deselected in 46.82s`。原 T07a 失败不覆盖，业务候选文件未变。

最终轮实际进行了 6532 次回调选择，保留 28 次慢调用。最长墙钟约 97.480 ms，最长线程 CPU 约 37.807 ms；前者主要等待，不能用墙钟最长推断 CPU 最忙。CPU 最忙的一次墙钟约 38.212 ms，在返回一个任务之前扫描了 **201 轮**：位置与 Battery 订阅各 200 次因 `entity._executor_event=true` 被排除，到末尾才各允许一次；同一批实体被反复检查，不是产生了 200 个新任务。

该次记录还包含 2412 次服务回调组不允许、402 次事件回调组不允许；它们是对活跃回调组的重复检查，不能计作失败的业务服务调用。返回时 Future 数为 3、工作队列为 0，这只是采样点，不构成完整线程利用率统计，也没有大量排队的证据。

原生剖析两轮的快照最大间隔约 211、290 ms；最终无 profiler 轮约 121.480 ms。与此前 Python profile 轮的 351 ms 间隔相比，观测方式改变后延迟明显减小。运行间调度和负载并未严格配对，因此不能声称全部差异都由 profiler 单独造成；但最终仍存在 201 轮、约 38 ms 的直接计数，确认循环扫描并非纯粹由 profiler 伪造。

三轮均返回真实空图片零检测并正常返航落地上锁，参数恢复核对通过，无 PX4/XRCE/图像桥残留。累计预算从 0.06417328 元增至 0.07267216 元，pending=false，未清零或扩额。全部原始记录及范围见 `artifacts/m6_dispatch_diagnosis/test_temp_review.md`。

#### 当前结论与后续

已定位本次忙计算的具体机制：Executor 在尚无可返回任务时，循环构造等待集、扫描实体并检查可执行性；已被调度但尚未取走的回调被反复排除，主线程消耗 CPU，工作线程仍需竞争执行机会。profile 会增加这条高频路径的成本，本次无 profiler 对照也保留了较短的循环。具体由哪次等待集唤醒或哪个锁/GIL 交互维持循环，尚无直接记录，不能进一步宣称某个 rclpy 缺陷或加线程能够解决。

原轮 533 ms 过期拒绝未在这些诊断运行中再现，不能宣布根因已全部确认或修复。下一批优先让功能验收使用必要的定点请求/响应记录，避免全线程 profile 污染时效测量，再复跑原固定集合；如仍失败，再针对等待集唤醒与回调组竞争补证据，不先改变线程数或放宽 Safety。本批不修改默认验收观察方式，T07a 仍未通过整组验收。

Ruff、默认关闭及 counters 模式的入口帮助检查、`git diff --check` 通过；面试 Q02 更新观测开销与真实循环的区别。未提交或推送。
