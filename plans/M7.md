## 2. 目标

一周内衡量 M6 的有用场景“多有用”：在固定多任务集合上自动运行、从实际状态和媒体判分、汇总普通/未见/扰动场景完成率，并输出相对同工具基线的差值、样本量和区间。

主输出为 `task_success_rate`、`unseen_success_rate`、`perturbed_success_rate`、`improvement_pp`，同时附 numerator/denominator、95% 区间、耗时、成本、安全违规和覆盖率。定义只在[测评设计](../docs/eval_doc/v1_evaluation.md)维护，M7 不重新定义评分公式。

所有 X 由运行产生，允许零或负提升；没有独立测试集不报未见成绩，正确停止不冒充业务目标完成。

## 3. 范围与约束

- 复用现有 PX4/Gazebo、相机、人物工具和 Agent 主链，候选评测环境取自第三方开源小仓库；仅接入世界文件和必需场景资产，不引入其机器人、导航或检测栈。M6 default 场景保留作回归与回退。
- B0/B1 均具备相同相机、检测与飞行动作。候选至多修改一处有 Dev 证据支持的 Agent prompt/配置，不训练工具、不放宽 Safety；较大业务或架构修复留后续。
- 分开普通、未见、环境扰动与工具故障组，必要的交叉组实际跑到才报告；每组列任务族和次数。已有 Dev 不能改名成未见，按[拆分规则](../docs/eval_doc/split_freeze_rules.md)保持任务族隔离。
- 环境扰动限选定仓库内的一种人物布局变化；具体点位与参数在 E01b2 修改前明确，不能把“空地换仓库”混同为单变量人物扰动。E05a 只接入已验证配置。工具故障仍限一种可控通信延迟/不可用，不建通用注入引擎。
- 返回值替身只验证评分和错误归因，不能混入真实模型/SITL 的系统成绩；工具效果问题不从目标完成率分母删除。
- 最终集和运行次数预先固定，只在 Dev 调整 B1；保留失败和缺失配对。小样本区间只作探索性结果，不据此宣称稳定泛化。
- 日志、费用和预算保护沿用现有机制；运行计划超出额度时先缩小并注明范围，不自动扩额、清零或只挑成功结果。

## 7. 止损、回滚与后续

到一周末仍阻断则列明缺失指标及原因，不补做新业务功能来转移目标，也不默认借用 RSI/面试时间。实验配置与注入可独立撤销，历史 artifacts 保留，M6 功能链回归不得受破坏。更多模型/架构/扰动及更大样本在已有报告后另排，不提前承诺正提升或统计显著。

E01b 保留 M6 原场景入口，回滚时停止本轮仿真、撤回新增布局/运行清单并恢复原配置；不改写旧证据。场景不就绪、无法满足任务族隔离或预算不足时，E01c 不标冻结完成，先交付具体缺口。当前主要风险是已有工具覆盖有限、未见族设计不成立及环境准备耗尽时间盒，不用扩大模型或工具研发来掩盖这些问题。

第三方资源缺失、许可链不清、Harmonic 迁移过重或场景运行占用不适合本机时，E01b1 交付失败证据及接入估计，不自动换模拟器、升级 PX4、增加避障算法或悄悄回退为空地作为仓库验收通过。

## 12. PX4 提示符日志问题定位与修复（2026-11-23）

### 12.1 目标与原因

本批唯一目标是查明并修复第 11 节的日志暴涨，避免正式地面链和后续评测持续生成无效提示符日志。复用现有生产启动器、相机采集器与状态适配器；增加的证据是实际 stdin、命令行、EOF 对照及提示符数量，原地面用例没有检查这些内容。

冻结 PX4 的 `platforms/posix/src/px4/common/px4_daemon/pxh.cpp:299–412` 中，`getchar()` 返回 EOF 时，`break` 只离开 switch；`update_prompt` 仍为 true，之后清行、输出提示符并进入下一轮。Bash 非交互后台命令没有显式输入重定向时，stdin 被设为 `/dev/null`，因此真实 PX4 在启动后持续读到 EOF，形成提示符忙循环。CMake 的 `gz_<model>` 目标不传 `-d`，而 HEADLESS 也不禁用 pxh。

`main.cpp` 的 `-d` 选项使启动流程在 rcS 完成后进入 `wait_to_exit()`，不创建本地 pxh；仍在前台进程中响应退出信号。该行为由固定版本源码和下列真实二进制对照共同核对，不将日志过滤当作修复。

### 12.2 定位证据

本批证据根目录为 [20261123](../artifacts/m7_pxh_fix/20261123/)。`test_temp_pxh.py` 用真实 PX4、实例 91 和独立工作目录运行 4 组 pytest；启动脚本仅 `exit 0`，没有 Gazebo、ROS、飞行模块或替换 PX4 对象。它验证命令行输入处理，不冒充完整生产链。各组均保存原日志及 `/proc/<pid>/fd/0`、cmdline，约 0.2 秒观察结果如下：

| 输入条件 | 实际 stdin | 提示符次数 | 观测日志字节数 |
|---|---|---:|---:|
| Bash 后台，未显式重定向 | `/dev/null` | 290,597 | 2,906,487 |
| Bash 后台，显式继承未关闭管道 | pipe | 1 | 527 |
| 前台管道，写端关闭产生 EOF | pipe | 277,684 | 2,777,357 |
| `px4 -d`，写端关闭 | pipe | 0 | 522 |

定位命令为 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /usr/bin/python3 -m pytest -q -o addopts= artifacts/m7_pxh_fix/20261123/test_temp_pxh.py`，结果 `4 passed in 0.90s`。保留运行目录，重复执行须另建证据目录，不能覆盖既有输出。
