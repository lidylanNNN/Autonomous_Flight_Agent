## 2. 目标

一周内衡量 M6 的有用场景“多有用”：在固定多任务集合上自动运行、从实际状态和媒体判分、汇总普通/未见/扰动场景完成率，并输出相对同工具基线的差值、样本量和区间。

主输出为 `task_success_rate`、`unseen_success_rate`、`perturbed_success_rate`、`improvement_pp`，同时附 numerator/denominator、95% 区间、耗时、成本、安全违规和覆盖率。定义只在[测评设计](../docs/eval_doc/v1_evaluation.md)维护，M7 不重新定义评分公式。

所有 X 由运行产生，允许零或负提升；没有独立测试集不报未见成绩，正确停止不冒充业务目标完成。

## 3. 范围与约束

- 复用现有 PX4/Gazebo、相机、人物工具和 Agent 主链，候选评测环境取自第三方开源小仓库；仅接入世界文件和必需场景资产，不引入其机器人、导航或检测栈。M6 default 场景保留作回归与回退。
- B0/B1 均具备相同相机、检测与飞行动作。候选至多修改一处有 Dev 证据支持的 Agent prompt/配置，不训练工具、不放宽 Safety；较大业务或架构修复留后续。
- 分开普通、未见、环境扰动与工具故障组，必要的交叉组实际跑到才报告；每组列任务族和次数。已有 Dev 不能改名成未见，按[拆分规则](../docs/eval_doc/split_freeze_rules.md)保持任务族隔离。
- 环境扰动限选定仓库内的一种人物布局变化；具体点位与参数在 E01b2 修改前明确，不能把“空地换仓库”混同为单变量人物扰动。E05a 只接入已验证配置。工具故障仍限一种可控通信延迟/不可用，不建通用注入引擎。
- 返回值替身只验证评分和错误归因，不能混入真实模型/SITL 的系统成绩；工具效果问题不从目标完成率分母删除。
- 最终集和运行次数预先固定，只在 Dev 调整 B1；保留失败和缺失配对。小样本区间只作探索性结果，不据此宣称稳定泛化。
- 日志、费用和预算保护沿用现有机制；运行计划超出额度时先缩小并注明范围，不自动扩额、清零或只挑成功结果。

## 7. 止损、回滚与后续

到一周末仍阻断则列明缺失指标及原因，不补做新业务功能来转移目标，也不默认借用 RSI/面试时间。实验配置与注入可独立撤销，历史 artifacts 保留，M6 功能链回归不得受破坏。更多模型/架构/扰动及更大样本在已有报告后另排，不提前承诺正提升或统计显著。

E01b 保留 M6 原场景入口，回滚时停止本轮仿真、撤回新增布局/运行清单并恢复原配置；不改写旧证据。场景不就绪、无法满足任务族隔离或预算不足时，E01c 不标冻结完成，先交付具体缺口。当前主要风险是已有工具覆盖有限、未见族设计不成立及环境准备耗尽时间盒，不用扩大模型或工具研发来掩盖这些问题。

第三方资源缺失、许可链不清、Harmonic 迁移过重或场景运行占用不适合本机时，E01b1 交付失败证据及接入估计，不自动换模拟器、升级 PX4、增加避障算法或悄悄回退为空地作为仓库验收通过。

## 8. E01a 实验草案与环境准备清单（2026-11-20）

本节定义当前评测任务、开源仓库环境准备和判据草案，不是可执行数据集或冻结协议。环境任务统一维护在第 8.3 节；具体仓库点位、高度和布局参数由 E01b2 明确，E01c 再冻结协议。

### 8.1 核对现状

已核对真实入口 `ros_agent_srv.main()`、[共享动作白名单](../ros2_ws/src/agent_comm/config/atomic_action_library.yaml)、[现有视觉飞行测试](../ros2_ws/src/behavior_executor/test/test_agent_visual_sitl.py)及 [T07a 逐轮汇总](../artifacts/m6_t07a/20261119T101248174390Z/test_temp_summary.json)。五个飞行动作及拍照/人物检测已接入；任务开始于终端输入，模型一次生成序列，执行器传递前项结果并在失败时停止，结束后再观察，不在每个动作后自动重规划。

T07a 已验证 P1 人物取证、P1/P2 两点人物取证和 P1 空场景。原 1 的“不要求检测、只拍照返航”在本轮尚无独立任务结果；它只能作为拟新增 Dev 条目，不能把带检测的旧结果直接改名。候选相关的 147 个文件仍与交接哈希相符；仅核对源码，不计新运行证据。

### 8.2 任务草案

下表 D01–D04 仅为本节条目编号，不是已建立的 Case ID 或独立任务族。P1/P2 表示 E01b2 将选定的两个仓库观察点，当前未确定坐标或高度；不沿用 M6 旧点位，也不创建地点解析服务。每条任务均从地面初态开始并要求最后返航着陆。

| 草案条目 | 原业务 | 拟提供给有人入口的任务目标 | 需要的环境 |
|---|---|---|---|
| D01 | 1 | 起飞至约定高度，到 P1 拍一张新照片，交付照片后 RTL；不要求人物检测 | 开源仓库、P1、相机与拍照服务 |
| D02 | 5 | 起飞至约定高度，到 P1 拍新照片并检查是否有人，返回检测结果和对应图片后 RTL | 仓库有目标配置、P1、真实 HOG |
| D03 | 5 | 与 D02 相同的中性检查目标，不提前告知无人，返回实际未检出结果和图片后 RTL | 仓库无目标配置、P1、真实 HOG |
| D04 | 2 | 起飞至约定高度，依次到 P1/P2，每点拍新照片并检测，逐点返回结果后 RTL | 仓库有目标配置、P1/P2、真实 HOG |

原 16 不新增飞行任务；E04/E08 汇总以上运行的指标和失败案例。D01 不因没有检测输出被判失败；D02/D03 不把“该图未检出”扩大成整个区域无人；D04 不用两次单点任务代替同一轮两点交付。

任务只向 Agent 提供观察点和业务目标；有/无目标配置、人物真值位置及预期检出数只供场景准备和 Grader 使用，不传入模型 prompt 或检测工具输入。

### 8.4 判据草案

以下判据限本轮评测草案，不修改 Safety、动作服务成功条件或现有测试。误差等数值拟参考 [T07a 两点用例记录](../artifacts/m6_t05b/20261119T101338615007Z/test_temp_case.json)，不是仓库已通过的结论；实际点位、高度和判据由 E01b2 明确并在 E01c 冻结，全部任务须在新环境实际运行后判分。

| 检查项 | 拟采用的任务判据与输出证据 |
|---|---|
| 到点与飞行过程 | 实际位置证明到达任务点：P1 水平误差不超过 0.5 米、P2 不超过 0.25 米，垂直误差不超过 0.5 米；沿用原独立轨迹检查的位移及采样间隔要求，不能只看 goto success |
| 本轮新图 | 文件可读取、哈希与元数据一致，采集满足现行服务契约，实际采集位置对应本点；新鲜度由原契约定义，不另放宽 |
| 检测与图片对应 | D02–D04 的每次检测消费紧邻拍照的真实媒体引用，返回 photo_id/路径/哈希与该图一致；仓库有目标各点须检出人物，无目标配置须成功零检测；服务错误不得改写为零检测 |
| 新布局真值 | 目标仍是同一人物，场景查询及原图确认其存在与可见情况；漏检或取不到有效目标图仍保留在正向目标结果中，区分工具效果与接入失败，不转为“无目标通过” |
| 两点交付 | D04 两份独立媒体，时间递增、位置分别对应 P1/P2，返航后终端产物仍可找到两点照片和结果；不复用前点图像 |
| 返航与交付 | 实际 RTL 过程、最终 landed=true/armed=false、距初始 Home 水平误差不超过 1 米；照片与适用的检测原始输出在最终交付可读 |
| 安全与故障 | 继续使用原批准、状态时效及失败即停规则；正常目标被拒绝算未完成。不得以清理仿真当作落地，安全违规与证据不足分别记录 |
| 任务超时 | 草拟从写入任务到本轮结束最多 240 秒，参照原有人入口等待上限；超时保留任务失败及末状态，不增加自动重试、返航或 Hold |

模型可选择满足任务约束的等价方案，不要求逐字匹配 M6 生成的序列；检测紧邻拍照仍由既有 `prev_output` 契约约束。端到端目标、预期错误处理、耗时/费用、覆盖率与失败归因统一按[评分口径](../docs/eval_doc/v1_evaluation.md#评分口径)执行，不在此定义新评分公式。
