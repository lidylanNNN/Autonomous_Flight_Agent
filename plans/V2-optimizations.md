# V2 优化清单

状态：待设计、待实施。这里的 V2 指产品迭代版本，不是 `SPEC_DEV.md` 的文档版本号；以下事项不纳入当前 V1/MX-4 实施批次。

## V2-1：集中聚合并通过 Topic 发布 WorldState

### 现状

- 观察服务与飞行动作服务分别创建 `Px4WorldStateAdapter`，各自订阅 PX4 消息并聚合状态。
- 适配器缓存 Python `WorldState` 快照，通过进程内 `read_world_state()` 提供读取；尚无 ROS `WorldState` 消息或共享 Topic。

### 目标

- 由独立状态聚合节点统一生成快照，通过 Topic 提供给观察节点和飞行动作节点，减少重复聚合。
- 统一状态 ID 和快照来源，便于跨进程追踪、录制与调试。

目标数据流（尚未实现）：

```text
PX4 --原始状态消息--> 状态聚合节点
状态聚合节点 --WorldState 消息--> 观察节点
状态聚合节点 --WorldState 消息--> 飞行动作节点
```

### 约束

- 统一发布源不保证订阅者同时持有同一快照；消费者仍须检查状态 ID、有效性和新鲜度。
- 保留 Gate 的状态检查，不以收到消息代替安全批准。

### 待决策项

- ROS 消息字段及其与现有 Python 模型的转换方式。
- Topic 名称、发布频率和 QoS。
- 时间戳语义、消费者状态年龄计算，以及首次无消息、消息过期和发布节点中断时的处理。
- 现有适配器、Backend 状态读取接口与 Trace 的迁移方式。

### 验证要求

- 从独立进程验证两个消费者接收同一发布源的状态，并按状态 ID 关联记录。
- 覆盖晚启动订阅者、消息过期、发布中断与重启；无有效状态时不得放行动作。
- 迁移后回归观察、Gate 和 PX4/Gazebo 动作链路。

## V2-2：可信 Authority

### 现状

V1 的授权假设见 [SPEC 第 5 节](../SPEC_DEV.md#5-安全不变量)；真实授权来源、撤销与失联机制尚未实现。

### 目标

在默认授权的 SITL 链路基础上，接入可核验的授权来源，覆盖授予、撤销、人工接管、失联、证据过期和派发前权限变化。

### 待决策项

- 权限来源、信任边界及部署方式；不预选操作员租约、UID 隔离或 RC 开关。
- 证据字段与时效、现有 reader 接口是否足够、异步等待和最终派发之间的复核与失败语义。
- 与 M7-S 运行中监测和抢占的职责边界；派发资格与执行中停止分别设计。

### 验证要求

从生产装配路径验证启动未知、授权、撤销、失联、过期和权限变化；失效零派发，并以真实 PX4 场景核对接管与恢复行为。
