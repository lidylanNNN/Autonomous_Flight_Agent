# V2 优化清单

状态：待设计、待实施。这里的 V2 指产品迭代版本，不是 `SPEC_DEV.md` 的文档版本号；以下事项不纳入当前 V1/MX-4 实施批次。

## V2-1：集中聚合并通过 Topic 发布 WorldState

### 现状

- 观察服务与飞行动作服务分别创建 `Px4WorldStateAdapter`，各自订阅 PX4 消息并聚合状态。
- 适配器缓存 Python `WorldState` 快照，通过进程内 `read_world_state()` 提供读取；尚无 ROS `WorldState` 消息或共享 Topic。

### 目标

- 由独立状态聚合节点统一生成快照，通过 Topic 提供给观察节点和飞行动作节点，减少重复聚合。
- 统一状态 ID 和快照来源，便于跨进程追踪、录制与调试。

目标数据流（尚未实现）：

```text
PX4 --原始状态消息--> 状态聚合节点
状态聚合节点 --WorldState 消息--> 观察节点
状态聚合节点 --WorldState 消息--> 飞行动作节点
```

### 约束

- 统一发布源不保证订阅者同时持有同一快照；消费者仍须检查状态 ID、有效性和新鲜度。
- 保留 Gate 的状态检查，不以收到消息代替安全批准。

### 待决策项

- ROS 消息字段及其与现有 Python 模型的转换方式。
- Topic 名称、发布频率和 QoS。
- 时间戳语义、消费者状态年龄计算，以及首次无消息、消息过期和发布节点中断时的处理。
- 现有适配器、Backend 状态读取接口与 Trace 的迁移方式。

### 验证要求

- 从独立进程验证两个消费者接收同一发布源的状态，并按状态 ID 关联记录。
- 覆盖晚启动订阅者、消息过期、发布中断与重启；无有效状态时不得放行动作。
- 迁移后回归观察、Gate 和 PX4/Gazebo 动作链路。

## V2-2：可信 Authority

### 现状

V1 的授权假设见 [SPEC 第 5 节](../SPEC_DEV.md#5-安全不变量)；真实授权来源、撤销与失联机制尚未实现。

### 目标

在默认授权的 SITL 链路基础上，接入可核验的授权来源，覆盖授予、撤销、人工接管、失联、证据过期和派发前权限变化。

### 待决策项

- 权限来源、信任边界及部署方式；不预选操作员租约、UID 隔离或 RC 开关。
- 证据字段与时效、现有 reader 接口是否足够、异步等待和最终派发之间的复核与失败语义。
- 与 M7-S 运行中监测和抢占的职责边界；派发资格与执行中停止分别设计。

### 验证要求

从生产装配路径验证启动未知、授权、撤销、失联、过期和权限变化；失效零派发，并以真实 PX4 场景核对接管与恢复行为。

## V2-3：失败后是否需要额外 Hold

### 现状

V1 已移除失败后自动 Hold 的设计与实施任务，决定记录见 [M5](M5.md#3-收口解析与有人交互)。当前 GoTo/Hold 成功后仍保持已有 Offboard 位置目标；Backend 在执行完成等待超时时已有 Auto Loiter 移交尝试，不代表所有失败均已安全处置。

### 待决策项

- 依据 V1 试验，确认是否存在 PX4 原生行为及现有 Backend 未覆盖、需要停止原目标并保持当前位置的具体故障；有证据后再决定是否设计额外 Hold。
- 区分 Gate 拒绝、明确执行失败、超时状态未知和通信失联，避免统一追加 Hold；明确与 M7-S 在途监测、抢占及人工接管的职责边界。
- 如确有必要，再确定触发条件、处置持有者、Gate 接线及结果记录；不预设固定 5 秒 Hold 或自动重试。

### 验证要求

以具体故障场景比较现有行为与新增处置的实际差异，证明新增安全收益；覆盖处置被拒绝、失败及原动作仍可能执行的情况。未取得必要性证据前，不作为 V1 的实施或验收前置条件。

## V2-4：从 M6 迁出的场景扩展

### 现状

2026-11-17 用户要求为 2 月面试、eval 和另行规划的 RSI 留出时间，将 M6 工期减半。从原 43 批迁出的 29 批保存在下表。当前 V1 分为一周 [M6 功能 Test](M6.md)及其通过后的一周 [M7 系统 Eval](M7.md)，不合并安排；曾将基础相机/视觉迁至 V2 的安排已撤销。当前均尚未实施。

### 目标

V1 系统性能评测收口后，按真实业务需求扩展场景。保留原调研任务编号：任务 1 的地点名/录像、任务 3/4 的 Orbit/Mission、任务 5 的衣着/三维定位/自主搜索、任务 6 的烟火、任务 7 的通用分支/循环、任务 8/14 的载荷、任务 9/10 的调度告警、任务 11/12 的建图变化、任务 13 的通用条件等待、任务 15 的语义检索，以及任务 16 的对话式运营查询。V1 eval 报告不算作任务 16 全部完成。

### 约束

- 不作为 V1 或面试准备的交付门槛，不因列入清单而租机、安装依赖或修改业务代码。
- 延续业务工具效果由对接方负责的边界；不把训练、微调或工具算法优化恢复进来。
- 优先本机、开源现成资源；需租赁的规模化场景后置，同档按新增改动量和依赖安排。
- 原工期仅保留迁移时的估计，不含等待与环境排障；V2 开始前按已交付 V1 接口重新评估，不能直接当作承诺。

### 实施步骤
