# 飞行 Agent 交互界面

## 现状

现有唯一有人入口为 `ros_agent_srv.main()`，输入后即由模型生成动作并交给执行器；没有独立规划确认阶段。桥梁两轮已有真实视频、输入、模型响应、Safety/状态 Trace 和结果文件，详见 [桥梁记录](bridge_demo.md)。当前无浏览器 UI。

## 目标

交付本地可操作界面：输入任务、查看实际模型动作、飞行状态、照片/录像和 Trace，并原样区分成功、拒绝与未执行。支持先审阅已有真实记录，再接入现有终端入口。

## 约束

不改变 Agent、执行器、Safety 及动作接口，不新增任务循环。不实现未经接入的规划确认、自动场景定位或急停。界面不能将历史录像或旧状态显示为实时。用户输入不得增加坐标、动作或其他隐藏要求。

## 实施任务

1. 界面批次：在现有 `scripts/` 下制作本地界面及已有记录浏览功能，支持选择本轮失败与此前详细指令演示、视频播放、Trace 展开及任务草稿。素材取自真实 artifacts，草稿不触发模型或飞行。
2. 入口接线批次（用户已确认）：本地 HTTP 桥接由启动脚本创建和持有实际 `ros_agent_srv.main()` 子进程，通过 JSON 行承载用户原文（包括换行），读取 stdout 及真实 Trace；一次只接受一个在该入口等待输入的请求。ROS/PX4 服务仍由现有环境流程装配，不由浏览器绕过 Gate 调用。

## 文件范围

界面文件与薄 HTTP 桥放在 `scripts/operator_ui/`，启动脚本放在 `scripts/`。本计划保存实施与验证记录；生产 ROS 源码与 Contract 保持原状。不增加外部 Web 框架依赖。

## 目标调用流

```text
操作员 --任务原文--> 浏览器界面
浏览器界面 --本地任务请求--> HTTP 桥
HTTP 桥 --stdin JSON 行编码原文--> agent_input.read_human
agent_input.read_human --原文返回值--> ros_agent_srv.main()
ros_agent_srv.main() --stdout 与既有 Trace 文件--> HTTP 桥
HTTP 桥 --状态、原文、执行记录及媒体引用--> 浏览器界面
```

后续模型与飞行调用仍按 [SPEC_DEV 第 4 节](../SPEC_DEV.md#4-ros-llm-对齐的目标调用链)，不建立第二条 ROS 控制入口。HTTP 桥拥有子进程，关闭桥时回收它；关闭终端入口不等于飞机急停，UI 不以关闭连接代替飞行处置。

## 验证

界面批次核对原文、模型动作、拒绝与恢复分离、媒体可播放、历史状态明确标识；检查桌面实际页面。接线批次在确认后核对等待输入/忙碌状态、原文传递、HTTP 错误及断开行为；优先复用已有真实入口集成用例，替身检查不计作 PX4/Gazebo 实飞。无用户触发时不得调用模型或执行动作。

## 回滚

停止本地服务器，移除本批界面和桥接文件即可恢复终端使用；不更改已有 Trace、录像或账本。

## 确认记录

用户已在本次会话确认“同意接入现有真实入口（推荐）”。新增桥接仅负责输入/展示，不更改飞行允许、拒绝或派发逻辑。

## 实施与验证记录（2026-11-25）

界面已提供历史选择、原文展示、实际模型动作、状态、媒体、可展开 Trace、入口终端和任务输入。历史录像、最近一次拍照和实时状态分别标识，不用旧录像冒充直播。完整规划确认、网页急停和视频直播未接入，按钮行为明确为“发送并执行”。

HTTP 桥通过独立管道接收实际主循环的输入就绪信号；不从 stdout 或模型文本推断可发送状态。JSON 行编码保留多行原文，不补充航点、顺序或上下文。新输入等待响应时不复用上一轮模型输出或成功报告。Trace 同时包含实际观察、模型响应及 Safety/动作结果，独立恢复依据已有明确恢复记录标记。

三个针对性测试通过：多行原文/忙碌拒绝（入口子进程替身，保留真实 OS 管道）、路径回退/符号链接逃逸、新任务不能复用旧轮结果。命令为 `.venv/bin/python -m pytest tests/test_operator_ui.py -q`；本批文件通过 Ruff、`node --check` 与 `git diff --check`。替身测试不计作 ROS/SITL 证据。

实际浏览器验证通过：在桥梁受控 SITL 地面上锁状态，经页面连接真实主循环并提交一次“拍一张新照片”；真实 Flash 仅输出 `capture_photo`，原文与 prompt 逐字一致，相机交付一张新 PNG；未起飞或移动。该轮费用 0.00195496 元。该验证只证明 UI 到现有生产链的地面采集，不证明桥梁原指令成功或 UI 飞行验证。

证据分别保存在 `artifacts/operator_ui_20261125/`（浏览器截图与页面检查）和 `artifacts/operator_ui_live_20261125/`（原文、实际 Agent/Safety/状态 Trace、结果及照片）。本地服务为 `http://127.0.0.1:8766`，实际浏览器已打开并恢复等待输入。SITL 服务保持运行供用户审阅，未自动派发后续任务。

## 使用

历史浏览：`bash scripts/start_operator_ui.sh --port 8766`。连接已启动的 ROS/PX4 环境时，传入 `--live-dir` 指定本轮 artifacts 目录，并使用与环境一致的 `ROS_DOMAIN_ID`；本轮为 85。页面点击“连接真实入口”后才能发送任务。

关闭页面不取消已提交任务。退出 HTTP 服务会关闭入口 stdin，不等同于急停；当前环境仍按已有 SITL 操作流程管理。本轮准备进程可通过创建 `artifacts/operator_ui_live_20261125/test_temp_stop_environment` 文件退出并恢复临时参数。
