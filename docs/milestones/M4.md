## M4-1 决策

- `MissionContract` 是冻结的后端所有契约，Planner 无权放宽。
- `SkillProposal` 保存原始 Skill 名与参数，非法内容由 Safety 给出可审计拒绝。
- 原因码是稳定机器字段，并与现有 Agent Dev 测评集保持一致。
- 只有 `APPROVE + CHECKS_PASSED` 能进入已批准命令生成流程。
- Human Approval 是中间仲裁状态，不等于批准执行。
- Geofence 的业务坐标采用 NED `north/east`，M0 Fixture 的 `x/y` 必须显式转换。

## M4-2 决策

- Schema Check 复用 `parse_skill_arguments()`，与 `ApprovedSkillCommand` 使用同一参数模型。
- 未知或 Contract 未授权的 Skill 返回 `SKILL_NOT_ALLOWED`。
- Mission 归属或 Skill 参数错误返回 `INVALID_SCHEMA`。
- State Check 先检查 Freshness，再检查 `based_on_state_id`，原因码顺序固定。
- 独立检查器只返回原因码，不提前承担 M4-7 Supervisor 的装配职责。

## 确定性检查顺序

1. Schema；
2. State Freshness / State ID；
3. Authority；
4. Current Vehicle State；
5. Command Sequence；
6. Geofence；
7. Flight Envelope / Mission Radius；
8. Resource / Battery；
9. System Health / Home Reference；
10. Human Approval。

检查器实现后，同一输入必须产生相同的 `SafetyDecision` 和 reason codes。
