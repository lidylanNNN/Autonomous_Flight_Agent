## 目标

Safety Supervisor。任何未获得 `SafetyDecision=APPROVE` 的 Proposal 都不能变成
`ApprovedSkillCommand`。

## M4-1 决策

- `MissionContract` 是冻结的后端所有契约，Planner 无权放宽。
- `SkillProposal` 保存原始 Skill 名与参数，非法内容由 Safety 给出可审计拒绝。
- 原因码是稳定机器字段，并与现有 Agent Dev 测评集保持一致。
- 只有 `APPROVE + CHECKS_PASSED` 能进入已批准命令生成流程。
- Human Approval 是中间仲裁状态，不等于批准执行。
- Geofence 的业务坐标采用 NED `north/east`，M0 Fixture 的 `x/y` 必须显式转换。

## M4-2 决策

- Schema Check 复用 `parse_skill_arguments()`，与 `ApprovedSkillCommand` 使用同一参数模型。
- 未知或 Contract 未授权的 Skill 返回 `SKILL_NOT_ALLOWED`。
- Mission 归属或 Skill 参数错误返回 `INVALID_SCHEMA`。
- State Check 先检查 Freshness，再检查 `based_on_state_id`，原因码顺序固定。
- 独立检查器只返回原因码，不提前承担 M4-7 Supervisor 的装配职责。

## M4-3 决策

- Authority 独立于 `WorldState`，只允许 `AGENT_ALLOWED` 执行普通任务 Proposal。
- Vehicle State 判断状态是否明确且满足 Skill 的基础观测要求。
- Command Sequence 只判断地面、空中和自动转换阶段的动作是否合法。
- `landed` 未知时，Sequence 也返回 `INVALID_VEHICLE_STATE`，独立调用仍拒绝该状态。
- GoTo、Hold 和 Land 要求 `position_valid=true`；RTL 的 Home 要求留给 M4-5。
- Home、Failsafe、Link 和 Health 不在 M4-3 重复检查。

## 确定性检查顺序

1. Schema；
2. State Freshness / State ID；
3. Authority；
4. Current Vehicle State；
5. Command Sequence；
6. Geofence；
7. Flight Envelope / Mission Radius；
8. Resource / Battery；
9. System Health / Home Reference；
10. Human Approval。

检查器实现后，同一输入必须产生相同的 `SafetyDecision` 和 reason codes。

## M4-4 独立检查器

- `check_geofence()` 检查 GoTo 目标点与当前位置是否位于扣除 `boundary_margin_m`
  后的局部 NED 矩形内。矩形是凸集，因此两端点在内时其直线段也在内；此项不保证
  PX4 实际飞行轨迹必然沿直线，也不能代替飞控固件围栏。
- `check_flight_envelope()` 检查 Takeoff/GoTo 的目标高度不超过任务上限。
- `WorldState.home_position_ned_m` 来自 PX4 `HomePosition` 的有效局部坐标，和
  `home_position_wgs84` 分别校验；`check_mission_radius()` 用它计算 GoTo 目标相对
  Home 的水平距离，不把 NED 坐标原点当成 Home。缺少有效局部 Home 时拒绝。
- 现有 Skill 参数没有目标速度，不能声称已检查目标速度上限；运动过程中的速度
  指令限幅仍由 PX4 的 `MPC_XY_VEL_MAX` 负责。`check_controller_speed_limit()`
  对传入的 PX4 限速值做确定性一致性检查：缺失、非有限或非正值返回
  `SYSTEM_UNHEALTHY`，大于任务上限返回 `SPEED_ABOVE_ENVELOPE`。
- `Px4ParameterAdapter` 使用 MAVLink 单参数读取协议，从目标 PX4 读取
  `MPC_XY_VEL_MAX`，记录 system/component ID 与接收时间。SITL 实测读到
  `12.0 m/s`，与 PX4 当前默认值一致。它高于目前单测任务的 `8.0 m/s` 上限，
  后续接入 Safety 后应拒绝该组合，不能自动放宽任务约束。
  `pymavlink` 由根项目 `uv` 环境提供。
- 适配器在消费读数前可校验参数名、目标 PX4 system/component ID、数值及
  调用方给定的新鲜度窗口；过期、未来时间或无时区时间均拒绝。窗口大小仍须
  由后续 Safety Supervisor 装配确定，并在每次放行前执行该校验和任务上限检查。
  当前单次读数不能直接当作执行批准。
- GoTo 的 Offboard 位置目标没有目标速度参数；`TrajectorySetpoint.velocity` 是
  前馈，不是速度上限。PX4 指令限幅也不保证实测速度绝不超限；实测速度持续监测、
  容差和超速处置需作为独立的运行中安全任务，不算 M4-4 已实现能力。

## M4-5 独立检查器

- `check_battery()` 要求电量读数、连接、有效性和无故障证据齐全；缺失或故障返回
  `SYSTEM_UNHEALTHY`，低于冻结任务下限返回 `INSUFFICIENT_BATTERY`，等于下限
  可通过。PX4 `WARNING_LOW` 本身不代替任务电量门槛。
- `check_system_health()` 要求 PX4 状态链路正常、无 failsafe 且故障检测清除；
  Takeoff 额外要求 preflight checks 通过。GCS 链路不作为机载 Agent 的通用前提，
  电池健康由 Battery 检查负责；所有缺失的必需证据均拒绝。
- `check_home_reference()` 对 RTL 始终要求有效全局 Home；其他 Skill 按
  `requires_home_position` 检查。它不代替 GoTo 的局部 Home NED 半径检查。
- 三项目前只对普通任务 Proposal 提供纯检查函数；紧急恢复动作的通行策略和
  生产执行前拦截留给 M4-7/M7，不能把独立测试当成已装配的 Safety Supervisor。

## 当前真实性边界

M4-3 已完成 Authority、Vehicle State 和 Command Sequence 独立检查器；M4-4
已完成围栏、目标高度、任务半径及 PX4 指令限速值的独立检查器，且已从 SITL 读取
真实 PX4 参数并实现读数校验；M4-5 已完成 Battery、Health 和 Home 独立检查器。
上述检查均尚未完成生产链路装配。Safety Supervisor、Human Approval、
Approved Command Factory 和执行链拦截尚未
实现，当前不得声称所有非法 Proposal 已能被生产链路阻断。
