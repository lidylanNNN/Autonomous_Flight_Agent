## 当前决策

- `FlightExecutionBackendProtocol` 只接受 `ApprovedSkillCommand`，原始 Proposal 不得直接下发。
- 执行开始前已有 `execution_id`，取消操作可以定位在途命令。
- Skill 参数使用 Pydantic Model，并拒绝未知字段、NaN 和无穷数。
- 业务边界使用正高度，PX4 Adapter 负责转换为 NED 向下轴数值。
- 原生 Takeoff 将相对 Home 高度转换为 PX4 所需的 AMSL 高度，缺少有效 Home Reference
  时不得构造起飞命令。
- 记录 PX4 ACK，但不把它当作任务步骤最终成功的证据。
- Registry 的 Required State 是供 M4 使用的元数据，不是内嵌 Safety Logic。
- M3-3 的 PX4 命令收发器串行关联 `VehicleCommandAck` 与 `execution_id`；ACK 仅表示
  协议接受或拒绝，不能替代后续 State Verifier 的任务完成判定。
- M3-4 的 Takeoff、Land 和 RTL 通过 PX4 Command Plan 启动，并根据实际
  `WorldState` 判定基础执行终态；命令 ACK 不作为 Skill 完成证据。
- M3-5 的 GoTo 和 Hold 通过 10 Hz Offboard 位置目标流执行；首次切换前预热生命信号，
  GoTo 根据实际位置收敛判定终态，Hold 根据连续驻留时间判定终态。
- 取消或超时结束通过 Offboard 执行的 Agent Flight Skill 时，先请求 PX4 Auto Loiter
  模式移交，收到接受 ACK 后再停止目标流，避免直接中断 Offboard 生命信号或继续追踪
  已超时的旧目标。

参见 `docs/adr/ADR-001-approved-skill-backend-boundary.md`、
`docs/adr/ADR-002-px4-flight-execution-route.md` 和
`docs/contract_specs/skill_contract.md`。
