# V1 有人主链测评设计

状态：2026-11-16 首版设计，基于 `632b045`（v0.10.88）核对。本文尚未执行测评，不构成通过结论；次数和通过门槛是首轮设计值，待评审后用于正式运行。

## 范围

目标：通过实际有人入口，分别测量动作执行、序列控制和人工反馈修正是否可靠，给出可重复、可定位原因的结果。

被测对象为 `ros_agent_srv.main()` 装配的有人主链。动作完成由动作服务判断，职责以[执行结果契约](../../contracts/skill_contract.md#执行结果)为准；测评程序读取证据判分，不参与运行时决策，也不新增 Verification 节点。

M7 必须有自己的行为验收与重复运行结果，不等待完整 Episode Runner 建成。现有 pytest 设施足以启动首轮测评设计；无人续跑、视觉任务、实机与运行中安全抢占不计入本次通过范围。

## 风险

- 动作响应成功但状态未达到要求：同时核对执行结果与状态采样，不只读取终端成功文字。
- 观察滞后：分别保存执行结束状态与下一轮观察；状态时间、来源或字段不一致须报告，不能用其中一份覆盖另一份。
- 失败后继续派发或自行调用模型：记录动作请求与模型请求时间，核对下一次人工输入前无新增行为。
- 替身覆盖范围被扩大：每次运行列出替换对象，替换的内部行为不计为已验证。
- 人工选取有利回复、重试后隐藏失败：首轮回复和每次尝试均保留，原失败不得覆盖。

## 案例执行与判分

每次 attempt 从固定初始条件开始，到返回结果和新观察并重新等待人工输入结束。M7 修正案例包括连续两轮人工输入，第二轮不得由执行器或模型自行触发。

首轮使用低空受控配置：起飞 3 米、系统上限 5 米、GoTo 北 3 米东 2 米、接受半径 0.5 米、Hold 2 秒；复用 M5 配置与恢复流程，不自动覆盖环境 manifest 或放宽 Safety 限制。RTL 额外记录本次 Home 和实际 PX4 返航参数。

状态判分阈值在运行前记录：起飞高度误差不超过 0.5 米；GoTo 水平误差不超过请求半径且高度误差不超过 0.5 米；Hold 在水平及高度 0.5 米容差内连续满足请求时长；Land 需 landed=true 且 armed=false；RTL 还需过程证据及返回 Home 的位置证据。阈值来自当前 Backend 配置的部分须与实际运行参数核对，不能在看过结果后调整。

测评侧采集的状态时间和来源必须与执行时间对齐；记录采样间隔与丢样。缺少时效上限、采样覆盖或必要终态字段时，状态证据判为不足，不凭旧快照判通过。采样不能证明采样间隔内的连续轨迹；Hold 的连续判断还需结合真实 Backend 执行记录。

拒绝与停止案例同时检查服务调用记录和 Trace；零派发检查还需先确认被测发布者已发现，再核对控制 Topic 消息。没有发布者的零消息不算零派发通过。

E05 分开记录两个结果：完整任务是否安全结束，以及 Gate 场景是否实际触发。模型自行拒绝可记为安全处理，但 Gate 场景为“未触发”，不能据此报告 Gate 拒绝通过。

## 测评数据

本轮先复用现有测试中的具体输入与本矩阵建立映射，不复制生成第二套同义数据，也不直接把 M0 的30条数据全数视为可执行。

首次数据核对逐条标记：可复用、需改参数或预期、当前不支持。含自动 Hold、无人重规划、拍照或识别的案例不能直接计入本轮分母；原始文件先保留，适配任务另批实施。

Dev/Validation/Frozen Test 的划分与冻结只遵循[拆分规则](split_freeze_rules.md)。本次不迁移 Family、不填充冻结集，也不宣称最终基准成绩。

## 环境与运行证据

环境以 [manifest](../../manifests/environment.yaml) 为准。每次运行另记实际 Python/ROS/PX4/Gazebo 版本、源码 commit 与工作区是否有改动、模型供应商及返回标识、完整 prompt、Safety 配置、Backend 容差、初始状态和测评脚本版本。

实际有人入口的目标证据流：

```text
[测评驱动/操作员] --预定人工文本与输入时间--> [ros_agent_srv.main]
[ros_agent_srv.main] --实际主链请求--> [观察/LLM/行为执行/飞行动作服务]
[飞行动作服务] --提案、决策、执行结果及状态记录--> [现有 Trace/运行 artifacts]
[现有 Trace/运行 artifacts] --原始响应、时间与状态证据--> [离线判分]
[离线判分] --逐条结果、失败原因与汇总指标--> [测评报告]
```

上图是测评设计；自动批量驱动、状态判分和汇总报告尚未完整实现。复用现有 artifacts 布局；临时记录遵守项目 `test_temp_` 命名要求，正式 Trace 保持既有名称。

每条结果至少记录：案例编号、attempt 编号、证据层级、替身范围、开始/结束时间、人工输入时间、模型调用次数、实际动作列表、相关提案/决策/执行 ID、执行与状态判分、证据路径、最终分类及失败原因。正式实现前再核对现有 Trace 可提供哪些字段，不另建运行时状态源。

## 指标与首轮通过标准

attempt 分类为：通过、行为失败、证据不足、场景未触发、环境未就绪。分类互斥；所有尝试计数均需公开。环境检查失败和人工中止也保留记录，不能通过删除日志提高成功率。

| 指标 | 计算方法 | 首轮设计门槛 |
|---|---|---|
| 场景通过率 | 通过 attempt 数 / 所有已进入被测入口的 attempt 数；证据不足、未触发也在分母 | 按场景与证据层级分别报告，不用混合总分替代 |
| Gate 触发后拒绝正确率 | 正确拒绝且零执行、零派发数 / 实际触发目标 Gate 条件数 | 100%；未触发单列，不算通过 |
| 序列控制正确率 | 满足按序、失败停止与等待人要求数 / 对应 attempt 数 | 100% |
| 假成功次数 | 服务 success=true，但必要状态证据明确不满足的次数 | 0；证据不足另列，不冒充假成功或通过 |
| M7 反馈接线正确率 | 第二轮 prompt 同时含实际执行诊断和新观察的次数 / M7 第二轮数 | 100%；实现前不报告为通过 |
| 人工反馈修正成功率 | 两轮流程及修正后状态均通过的次数 / M7 已启动 attempt 数 | 逐例报告通过数/总数；不得称无人恢复成功率 |
| 延迟与成本 | 模型耗时、动作耗时、整轮耗时、token/账本成本 | 逐次值及中位数、最大值；首轮不设无依据的性能门槛 |

离线确定性回归须全部通过。真实模型/SITL 的首轮设计为 E01–E05 各3次完整尝试；E01/E02 可复用同一场起降的两轮，E03 可复用其中的 GoTo/Hold 证据，保留逐项结果而不重复计算独立飞行次数。M7 实现后 E09 再运行3次真实两轮尝试，E10 先以替身验收。

每场重复运行重置到该场景的初始条件；模型规避或失败均保留，不无限重试直到凑足成功。正常场景首轮目标为3/3；出现行为失败、假成功、证据不足或未触发时，该场景不宣称验收通过，并报告具体缺口。3次重复仅为开发验收，不能声称统计可靠性或生产成功率。

真实模型运行前按既有预算保护设置总额，预算不足则停止并记录剩余项；本设计不自动启动付费请求或 SITL。

## 实施任务与回归

1. 证据映射：把现有测试/历史记录映射到矩阵，核对上述每条断言的真实来源、替身范围与缺失字段。
2. 最小重复运行：复用现有 pytest 和 artifacts 收集，先支持当前可执行场景的逐次结果与汇总；不先开发通用 Episode 框架。
3. M7 纵向验收：在反馈接线实现批次中补齐 E08–E10，从实际人工入口验证；已有失败即停与观察测试直接复用。
4. 状态证据核对：补齐必要时间、来源及终态对照，输出 E12 的不一致报告；不得以测试判分逻辑替代产品动作服务判断。
5. Dev 数据适配：在上述路径可重复运行后处理旧数据与当前能力差异，再按既有拆分规则推进 Validation 和 Frozen Test。

每个实施批次只完成一个可验证目标，修改前按 AGENT.md 汇报；接口、依赖或发布门槛变动另行评审。本文件不授权顺带修改业务行为。

验证时先运行被修改路径的既有组件与 ROS 集成回归；真实模型/SITL 单列运行。新增用例只补此前缺失的组合、反馈接线、重复统计或状态证据，不重复建设已有 ACK、完成条件与失败即停单测。
