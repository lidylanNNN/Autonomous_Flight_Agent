# V1 eval_harness 系统量化测评

状态：尚无系统评分结果。旧 M7 反馈修正阶段已取消；本文件定义系统评分及证据口径，不代表评测已实现。

2026-11-17 阶段安排：先完成一周的 [M6 功能 Test](../../plans/M6.md)，再开展一周的 [新 M7 系统 Eval](../../plans/M7.md)，分别交付，不合并执行计划。新 M7 不恢复旧反馈修正设计。

## 目标

构建基于 ROS 2/PX4 SITL 的 Flight Agent 自动化评测体系，覆盖多任务、未见任务/场景和可复现扰动，自动输出端到端目标完成率、未见场景完成率、扰动场景完成率，以及候选 Agent 相对冻结基线提升的百分点。所有数值由实际运行计算，允许零提升或负提升，不预填成绩。

按用户给出的层级，L4 结果评测是必达主输出，L5 用独立任务组和可复现扰动限定泛化/鲁棒性范围，L6 用配对基线对照和不确定性估计支持比较。L3 工具调用用于解释成败；L1/L2 测试只能验证测评程序和组件，不能代替上述系统指标。工具业务效果不优化的职责边界见 [SPEC_DEV](../../SPEC_DEV.md#1-项目定义)，这不取消真实任务结果判分。

单个 SITL 用例通过只是一条运行证据，不等于完成系统测评。`eval_harness` 必须将任务集合、运行记录、逐任务判分和汇总指标关联起来。

实施前置条件是 [M6 的 T1 视觉场景功能门槛](../../plans/M6.md#t1先证明场景有用)：先增加视觉能力，并以实际入口/相机/检测工具的功能 test 证明任务可用，再进入本设计的 eval。功能通过不是系统性能成绩；纯起降用例或 Mock 通过也不能替代该前提。

## 现状

`eval_harness/` 当前只有包占位，没有 Episode Runner、Grader 或汇总报告实现。`agent_benchmark_sets/dev/` 有30条任务数据；Validation 与 Frozen Test 仍为预留。现有 M4/M5 pytest 和 artifacts 提供运行及采集经验，不直接充当30条任务的评分结果。

Dev 数据中的参数、自动恢复与视觉任务预期部分超出现有能力。先逐条记录支持情况，不修改任务目标迁就实现。T1 后的正式集合包含有用视觉任务及多点变体；基础五动作任务用于回归和对照分层，不把它们单独包装成视觉业务评测，覆盖比例公开。

## 最小调用流

以下是待实现的测评链，不能作为已有实现事实：

```text
[agent_benchmark_sets] --任务、初始条件、限制、预期结果--> [eval_harness Runner]
[eval_harness Runner] --自然语言任务及预定人工输入--> [实际 ros_agent_srv 入口]
[实际主链及 PX4/Gazebo] --观察、模型响应、执行结果、状态与时间--> [本次 Episode artifacts]
[本次 Episode artifacts] --原始运行证据与对应任务预期--> [eval_harness Grader]
[eval_harness Grader] --逐任务判分及判分原因--> [eval_harness Reporter]
[eval_harness Reporter] --任务结果、覆盖率及系统指标--> [JSON 与可读报告]
```

Runner 负责环境准备、输入、超时和回收，复用已验证的运行设施。Grader 只在测评侧根据任务 required/forbidden outcomes 和原始证据判分，不新增产品 Verification 节点，不参与动作选择。

## 评分口径

第一版输出指标向量与逐任务结果，不先用任意权重压成一个总分。

### 主输出：系统性能

| 输出字段 | 定义与证据要求 |
|---|---|
| `task_success_rate` | 已达到真实业务目标且无 forbidden outcomes 的正向任务运行数 / 已启动正向任务运行数；从实际状态判目标，不只信工具 success/ACK |
| `unseen_success_rate` | 未参与 Agent/prompt 开发与挑选的独立测试任务组的目标完成率；标明未见的是任务族、环境布局还是二者 |
| `perturbed_success_rate` | 预先固定扰动类型、强度、触发时刻及种子的正向任务目标完成率；按环境扰动/工具故障分别报告 |
| `improvement_pp` | 相同任务、初态、扰动和种子下，100 ×（候选目标完成率 − 基线目标完成率）；单位是百分点，不能写成相对百分比 |
| `success_ci95` / `improvement_ci95` | 完成率及配对差值的 95% 区间，附独立任务族数、运行次数与计算方法；样本不足或无法有效估计时明确标记 |
| 时间、成本与安全 | 任务输入至终态的耗时、模型调用/token/费用、安全违规率；成功与失败分别统计，缺失费用不填成零 |

每个成功率同时输出 numerator、denominator 和任务覆盖率，按每类任务和全部预定集合分别汇总。先在 manifest 固定整体聚合方式，再运行，不能按结果挑权重；跨任务族的重复采样不能冒充更多独立任务。

**目标完成和验收通过分开**：现有故障任务的 required outcomes 可能明确要求 `mission_failed` 或 `not_marked_success`。满足它们可以让预期结果检查通过，但正向飞行目标仍未完成。此类拒绝/故障处理另输出 `expected_outcome_pass_rate`、`safe_stop_rate`；纯不安全请求的拒绝测试单列，不混入正向目标完成率。不能靠大量“正确拒绝”抬高端到端飞行完成率。

### 诊断输出：Agent 工具调用

每个任务在运行前定义允许工具、等价方案、参数与必要先后关系，不强制匹配唯一标准序列。语法有效不等于工具选择或参数语义正确；以下指标解释系统得分，不替代目标完成率。

| Agent 指标 | 定义 |
|---|---|
| 工具选择正确率 | 工具符合当前任务、观察及可用能力的调用数 / 实际工具调用数；不应调用时的多余调用计错 |
| 必需调用覆盖率 | 已正确发起的必需调用项数 / 场景中适用的必需调用项数；漏调不能被工具选择正确率掩盖 |
| 参数正确率 | schema、值、单位、坐标系及数据引用均满足要求的调用数 / 实际工具调用数 |
| 顺序与结果传递正确率 | 正确满足先后关系及前项输出引用的检查项数 / 本次适用检查项数 |
| 失败处理正确率 | 遵守契约的停止、错误/超时处理和状态报告检查项数 / 已触发的适用检查项数；不要求未实现的自动恢复 |

无适用项的指标记为不适用，不记成 100%。模型输出有效率、Agent 调用次数/token/费用及编排耗时作为补充；总任务耗时中工具执行时间单列，避免把工具计算慢直接归因于 Agent。

下表补充整体运行记录。工具返回错误业务结论而 Agent 正确调用时，目标完成仍可能失败，错误归因不能从完成率分母中删除该运行。

| 指标 | 定义 |
|---|---|
| 预期结果通过率 | 满足全部 required outcomes 且未触发 forbidden outcomes 的任务运行数 / 对应已启动任务运行数；不与正向目标完成率混称 |
| 安全违规率 | 有明确状态或派发证据证明违反任务安全要求的运行数 / 已启动任务运行数；无法判定单列 |
| 模型输出有效率 | 能被当前生产提取器和执行器接受的行为回复数 / 实际模型回复数 |
| 动作成功率 | 返回成功且任务所需状态证据满足的动作数 / 已发起动作数；证据不足单列 |
| 任务耗时 | 任务输入至结束的逐次耗时；汇总中位数、最大值，成功与失败分别报告 |
| 模型开销 | 每任务请求次数、输入/输出 token、账本估算费用；缺失 usage 单列 |
| 数据集覆盖率 | 已实现运行与判分支持的任务数 / 所选 split 的全部任务数 |

已启动但任务超时、系统失败或证据不足的运行保留在对应完成率/通过率分母中。环境在输入前未就绪的尝试单列为启动失败，报告计划运行数、实际启动数和启动失败数，不把它算作任务成功。

要求拒绝的不安全任务可以判为预期结果通过；正常飞行任务被拒绝则为目标未完成。运行中没有派发不能自动证明安全评分通过，须核对该任务要求的证据。

unsupported 任务单列并进入覆盖率分母，不报告成系统已完成或已通过。运行前确定任务集合和重复次数；失败记录不被重试覆盖，不做只挑成功任务的汇总。

### 失败归因

| 情况 | 归因与处理 |
|---|---|
| 选错工具、漏调、传错图像/坐标、顺序错误、未按契约处理失败，或无依据地宣称成功 | Agent 调用问题，属于 V1 修复范围 |
| 正确调用后检测漏检/误检、重建精度不足等 | 工具业务效果问题，保留原始输出及任务失败事实，交业务对接方处理，不在 V1 优化模型 |
| 依赖缺失、图像桥接或适配失败、服务不可用、资源不足 | 接入/运行问题；定位具体环节，不能归成模型准确率问题，也不能在未定位时一律归给业务方 |
| 同时存在多类问题，或证据不足 | 分别记录或标为待定位；不为了提高 Agent 分数排除该运行 |

例如，业务目标是“识别黑色外套人员”：Agent 应传递正确图像和该目标描述，并遵守工具能力与返回值契约。工具漏检由业务对接方负责；Agent 把“未检出”说成“现场无人”，仍是 Agent 问题。缺少所需能力的工具应记录为不支持，不能用只能识别人形的工具输出冒充衣着识别。

## 基线、未见任务与扰动设计

- **基线**：T1 通过后、基于 Dev 进行 Agent 改进前，冻结具有相同视觉工具能力的未优化 Agent 源码、prompt、模型标识、工具版本和 Safety 配置作为 B0；B1 只基于 Dev 问题改进 Agent。不能用不具备视觉工具的旧版本作主基线，或故意削弱工具制造提升。M5 的三个验收结果不直接充当 B0 完整评分。
- **开发与未见任务**：现有 Dev 30 条已可见，不能改名后宣称未见。按[拆分规则](split_freeze_rules.md)建立不与 Dev 重叠的新任务族，关联的正常/边界/故障变体保持在同一 split；参数随机化或换 seed 单独标注，不能自动宣称任务级泛化。只在 Dev 调整 B1，最终测试集按既有规则冻结；查看最终结果后再调优须新建测试版本，不能继续声称原结果无泄漏。
- **环境扰动**：在 [M7 选定并验证的评测环境](../../plans/M7.md#83-环境准备任务)中，固定一种最小可复现布局变化；普通组与扰动组使用同一世界版本，原环境的历史运行不直接替代新环境结果。参数、种子与实际画面/场景生效证据须记录，不能只写 manifest 就当成已注入。工具效果问题保留在任务结果中，不转为视觉算法优化任务。
- **工具故障**：至少选择一种可控的延迟/不可用故障，在实际 ROS 服务通信边界注入，生产 Agent、Gate 和 PX4 Backend 仍实际执行；返回值替身作为独立诊断组。故障原本使目标不可能完成时保留零/低完成率，另报安全停止，不虚构恢复能力。
- **运行分组**：分别报告常规任务、未见任务、常规任务＋扰动、未见任务＋扰动；未运行的组合记未覆盖，不能把“未见/扰动”混成一个更好看的数字。每组按环境扰动和工具故障细分。
- **配对重复**：B0/B1 使用相同 case、初态、外部扰动种子和预定人工输入，记录运行顺序并交错执行，模型采样不可控时如实标注；每次独立启动/重置。固定重复次数，失败不被重试覆盖。
- **对照与消融**：B0/B1 主对照之外最多一个 Agent 变量消融，不改工具算法、飞控或 Safety 规则。没有测得提升就报告无提升；区间含零时不声称稳定提升。
- **不确定性**：先输出任务族数和全部原始配对结果；汇总区间以任务族为重采样单元，保留族内重复和 B0/B1 配对。小样本区间仅作探索性描述，不能用随机种子重复堆出虚假的独立样本数。具体重采样方法及种子在运行前固定；实现可参考 [SciPy 配对 bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)，不据此要求增加生产依赖。

## 首个纵向切片

1. T1 通过后，选择一个已可完成的 Dev 视觉取证任务，核对目标、初始条件、图片/检测结果与返航要求，明确 Runner 与 Grader 输入输出；不先铺设通用故障框架。
2. 复用 T1 真实入口和设施运行该任务，保存实际飞行、图像、检测输出及开销，再由 Grader 自动判分。
3. 在相同版本和任务集合上重复运行、汇总指标，得到首份基线报告；随后扩展其他正常任务及拒绝任务。
4. 从报告中选择实际失败或缺失证据，再决定是否修改产品代码、数据适配或运行设施。

实现顺序是先以功能 test 证明任务可用，再让同一任务贯通 Runner、Grader、Reporter，最后扩展未见/扰动集合。已有 Dev 任务目标保持原义；新增视觉任务版本单独记录，不拿功能用例、3米起飞或新观察请求替代任务要求的真实结果。

## 数据与证据

数据 schema 与拆分仍遵循现有 `agent_benchmark_sets/schemas/` 和[拆分规则](split_freeze_rules.md)，不在本次文档更新中修改数据或 schema。首个切片只产出 Dev 基线；完成独立任务族、冻结与实际运行后才报告对应未见场景成绩。当前 Validation/Frozen Test 为空，尚无泛化指标。

每次运行绑定源码 commit、工作区差异、环境 manifest、任务与数据版本、模型标识、完整 prompt、Safety 配置、状态时间与来源、执行 ID、判分程序版本及证据路径。配置与参数在运行前记录，不能看过结果后修改阈值。

已有 SITL fixtures 可以复用其进程、订阅与清理逻辑；实际模型、PX4 和 Backend 仍需真实调用。替身运行单独报告，不并入真实模型/SITL 的系统指标。

## 验证

验证 Grader 能区分真实目标完成、故障处理通过、工具效果失败、调用错误、安全拒绝、超时和证据不足；验证 Reporter 的分组、分子分母、百分点差值和区间可由原始配对数据重算。可用明确标源的工具替身检查评分程序，但不得据此宣称真实视觉、鲁棒性或 SITL 成绩。再用实际 Episode 核对端到端运行及最终报告。测试通过不替代评分运行。
